TUJUAN UTAMA
Bangun aplikasi Portal Satu Data Bulungan yang sesuai dengan dokumen di master package, dengan tetap memberi ruang untuk improvement, perbaikan teknis, penyederhanaan, atau penyesuaian implementasi selama:
1. tidak keluar dari tujuan utama proyek,
2. tidak bertentangan dengan kebutuhan inti,
3. tetap konsisten dengan identitas visual Bulungan,
4. tetap realistis untuk dijalankan secara lokal pada tahap awal,
5. setiap iterasi melanjutkan iterasi sebelumnya tanpa merusak fitur yang sudah bekerja.

BATASAN DAN ARAH IMPLEMENTASI
1. Portal tetap diposisikan sebagai 1 aplikasi web publik yang terlihat sebagai 1 website dengan 1 domain.
2. Arsitektur target yang disepakati:
   - Next.js sebagai frontend publik
   - CKAN sebagai backend katalog data
   - PostgreSQL + Solr + Redis sebagai service inti CKAN
   - CKAN DataStore tetap disiapkan
   - Superset dan object storage tidak wajib pada fase awal
3. Pada tahap pertama, aplikasi harus sudah bisa dilihat dan dijalankan secara lokal.
4. Jika integrasi penuh CKAN pada tahap pertama terlalu berat untuk membuat aplikasi cepat terlihat di lokal, Anda boleh membuat vertical slice yang tetap mengarah ke arsitektur final, misalnya:
   - frontend Next.js sudah jadi dan runnable,
   - adapter integrasi CKAN sudah disiapkan,
   - data awal bisa disediakan dari seed/mock terstruktur,
   - tetapi struktur dan kode harus memudahkan transisi ke CKAN nyata tanpa rewrite besar.
5. Jangan melakukan over-engineering. Fokus pada jalur implementasi yang stabil, terukur, dan mudah diteruskan.
6. Jangan ubah isi folder `references` kecuali diminta. Simpan semua hasil implementasi, catatan, dan kode di luar folder itu.

ARAH TEKNIS FASE 1
Gunakan pendekatan yang paling aman:
1. Siapkan frontend Next.js sebagai aplikasi utama yang bisa jalan lokal.
2. Siapkan lapisan integrasi data yang bersifat adapter/service, sehingga sumber data bisa:
   - sementara dari seed/mock,
   - lalu mudah diganti ke CKAN API tanpa mengubah UI besar-besaran.
3. Bila memungkinkan dan realistis, siapkan juga environment lokal berbasis Docker Compose untuk:
   - CKAN
   - PostgreSQL
   - Solr
   - Redis
4. Tetapi jangan sampai upaya integrasi penuh menghalangi tercapainya target utama fase 1: aplikasi harus bisa dilihat dan dijalankan lokal.

RULES UNTUK ITERASI BERIKUTNYA
Setiap iterasi berikutnya harus:
1. membaca `docs/04_changelog.md`
2. membaca status kode saat ini
3. melanjutkan dari kondisi terakhir
4. tidak menghapus fitur yang sudah berjalan kecuali diganti dengan versi yang lebih baik dan tetap stabil
5. melakukan validasi sebelum menyelesaikan iterasi
6. memperbarui changelog dan next step

QUALITY GATE WAJIB SETIAP ITERASI
Sebelum menutup iterasi, lakukan:
1. cek project structure
2. cek tidak ada import rusak
3. cek halaman utama tetap bisa dibuka
4. cek build atau minimal compile tidak error
5. cek styling utama tidak pecah
6. cek route yang sudah dibuat masih berjalan
7. catat hasil verifikasi di changelog

JIKA TERJADI BLOCKER
Jika ada blocker:
1. jangan berhenti terlalu cepat,
2. cari jalur implementasi alternatif yang paling aman,
3. gunakan mock/adapter/stub bila perlu,
4. dokumentasikan blocker dan solusi sementaranya,
5. lanjutkan pekerjaan sejauh mungkin.

FORMAT LAPORAN SETIAP ITERASI
Di akhir setiap iterasi, berikan ringkasan dengan format:
1. apa yang dibaca/dipahami
2. apa yang dibangun/diubah
3. file utama yang dibuat/diupdate
4. status run/build/test
5. asumsi atau keputusan baru
6. next step paling logis
