## PRIORITY 1 - Critical session security

Bug:
- Session internal dapat dipalsukan karena cookie hanya base64 JSON tanpa signature.
- File terkait yang perlu diperiksa:
  - `web/src/lib/utils/internal-auth.ts`
  - `web/src/lib/utils/internal-auth-server.ts`
  - semua guard auth internal
  - route login/logout internal

Tugas:
1. Ganti mekanisme session plain-base64 menjadi signed/encrypted session.
2. Minimal gunakan HMAC signature dengan secret server-side.
3. Jangan simpan secret di client.
4. Pastikan cookie tetap `HttpOnly`.
5. Pastikan payload cookie yang dimodifikasi manual ditolak.
6. Pastikan session lama/plain-base64 tidak lagi diterima.

Acceptance criteria:
- Cookie forged role admin tidak bisa lagi mengakses `PATCH /api/internal/settings`.
- Request dengan cookie invalid return `401`.
- Login valid tetap menghasilkan session valid.
- Logout tetap clear cookie.
- Tambahkan test untuk:
  - valid session accepted
  - tampered session rejected
  - forged admin rejected

## PRIORITY 2 - Login fallback CKAN ke local

Bug:
- Saat CKAN down, `POST /api/internal/auth/login` gagal `500 fetch failed`.
- Fallback local store tidak dieksekusi.

File terkait:
- `web/src/app/api/internal/auth/login/route.ts`
- service login CKAN
- local auth service

Tugas:
1. Bungkus call login CKAN dengan try/catch.
2. Jika CKAN network error/unreachable, lanjutkan fallback local.
3. Jika credential invalid di CKAN, tetap evaluasi fallback local sesuai desain saat ini.
4. Jangan return raw `fetch failed` ke client.
5. Bedakan error credential invalid vs upstream unavailable.

Acceptance criteria:
- Dengan CKAN down dan credential local valid, login sukses.
- Dengan CKAN down dan credential invalid, login gagal aman dengan status 401.
- Response tidak membocorkan stack trace.
- Test otomatis atau script verifikasi tersedia.

- `web/src/lib/services/internal-store.ts`

## PRIORITY 4 - Operator ownership enforcement pada workflow transition

Bug:
- Operator bisa transisi dataset OPD lain untuk transisi yang secara role diperbolehkan.

File terkait:
- `web/src/app/api/internal/workflow/transition/route.ts`
- `web/src/lib/services/internal-store.ts`
- workflow permission helper

Tugas:
1. Sebelum transition, ambil dataset target.
2. Jika role `operator_opd`, pastikan dataset organisasi sama dengan session organisasi.
3. Jika tidak sama, return 403.
4. Pastikan valid transition tetap memakai aturan workflow resmi:
   - Draft -> Submitted
   - Submitted -> Need Revision | Approved
   - Need Revision -> Submitted
   - Approved -> Published
   - Published -> Archived
5. Jangan merusak hak admin dan walidata.

Acceptance criteria:
- Operator OPD A transisi dataset OPD A Need Revision -> Submitted -> sukses.
- Operator OPD A transisi dataset OPD B Need Revision -> Submitted -> 403.
- Operator tetap tidak bisa Approved/Published/Archived.
- Admin tetap bisa override sesuai aturan.
- Test direct API tersedia.

## PRIORITY 5 - API error contract

Bug:
- API internal tanpa auth redirect 307, bukan JSON 401/403.
- Unauthorized action return 500, bukan 403.

File terkait:
- `web/src/proxy.ts`
- API route internal
- error helper/response helper jika ada

Tugas:
1. Pisahkan behavior page internal dan API internal.
2. Untuk `/internal/*` page tanpa login: redirect boleh.
3. Untuk `/api/internal/*` tanpa login: return JSON 401.
4. Untuk role tidak berhak: return JSON 403.
5. Jangan gunakan 500 untuk error permission.
6. Standarkan response shape JSON.

Acceptance criteria:
- GET/POST `/api/internal/*` tanpa session -> 401 JSON.
- Role salah -> 403 JSON.
- Validasi salah -> 400 JSON.
- Error server asli -> 500 JSON.
- Tidak ada redirect HTML untuk API internal.
